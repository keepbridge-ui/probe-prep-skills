# Probe Prep Skills

AI 사용이 허용된 코딩 단계에서 명시적으로 불러 쓰는 범용 준비 지침 세 개다. 스킬은 AI가 특정 작업을 할 때 읽는 지침으로, 예를 들어 `$plan`를 선택하면 요구 확인 지침을 읽는다. 공개 원칙을 참고해 새로 작성했으며 Cofa Probe의 공식 스킬·공식 승인 자료·정답 모음이 아니다. 실제 시험 문제·파일·개인 정보·비공개 프로젝트 자료를 포함하지 않는다.

## 세 스킬

| 단계 | 호출 | 역할 |
| --- | --- | --- |
| 시작 | `$plan` | 막연한 요청을 중요한 질문 하나씩으로 구체화하고 대안·완료 기준 확인 |
| 구현·수정 | `$build` | 실패 재현·원인 확인·최소 수정·검사, 핵심 기능의 흐름과 관련 파일 설명 |
| 완료 전 | `$check` | 요구와 실행 근거 대조, 중요한 지점에서 한 질문씩 사용자 설명과 실제 코드 비교 |

파일은 `.agents/skills/<스킬 이름>/SKILL.md`에 있고 각 `agents/openai.yaml`은 `allow_implicit_invocation: false`다. 이는 자동 선택을 끄는 설정이다. 제공 Codex가 지원하면 요구 확인이 필요할 때처럼 필요한 단계만 직접 불러 쓴다. 이 묶음은 지침과 고지로 구성되며 외부 AI, 자동 실행 코드, 여러 AI에 작업을 나누는 자동화나 자동 게시를 포함하지 않는다.

## 시험에서 먼저 확인할 조건

아래는 제작 시 전달받은 가이드의 제한을 운영 전제로 반영한 것이다. 원문 시험 가이드와 과제별 최신 안내를 이 자료가 대신하지 않으며, 실제 안내가 항상 우선한다.

- 제공된 환경의 Codex만 사용한다. 외부 AI·개인 API 키·Computer Use·외부 브라우저 직접 접근은 사용하지 않는다.
- 서브에이전트는 검토 일부를 다른 AI에 맡기는 것처럼 작업을 나눠 맡는 다른 AI다. 인터뷰에서 언급됐다는 이유만으로 시험 사용 허가를 추정하지 않는다. 실제 안내의 허용을 확인해야 하며 이 묶음은 자동 호출하지 않는다.
- 시험 문제·파일·결과를 외부로 전송하거나 Git push하지 않는다. 개인 PC의 파일이나 준비 ZIP을 시험 환경에 업로드하지 않는다.
- 일반적으로 공개된 저장소의 범용 Skill·지침·코드는 최신 안내가 허용하는 경우에만 제공 환경의 AI를 통해 공개 clone·다운로드로 취득한다. clone(클론)은 공개 자료를 작업 환경 안으로 복사받는 것으로, 여기서는 준비 스킬 파일을 제공 환경 안으로 받는 일이다. 공개되어 있다는 이유만으로 개별 과제의 허용을 단정하지 않는다.
- **준비 저장소는 결과 통지까지 공개 상태로 유지한다.** 시험 중 이 저장소에 시험 자료·답안·실행 결과를 추가하지 않는다.
- **코드 제출 후 AI·복사 붙여넣기 금지 서술형 단계에서는 세 스킬 모두 즉시 중단한다.** 답안·개요·문장 다듬기·이전 기록을 이용한 답안 작성뿐 아니라 이해 확인 질문·용어 설명 등 어떤 지원도 하지 않는다. 그 단계에서 아래 요청문도 AI에 입력하지 않는다.

목표는 결과물 완성과 실제 협업, 본인의 코드 이해를 함께 높이는 것이다. 중요한 구조 선택이 아직 정해지지 않았다면 AI가 현실적인 대안과 장단점·추천 이유를 쉽게 설명하고 사용자가 판단한다. 예를 들어 앱을 닫아도 메모를 남길지처럼 결과에 영향을 주는 선택이다. 사소한 수정마다 승인을 요구하지 않는다.

요청이 막연해도 완성된 기획서가 필요하지 않다. `$plan`이 목적·누가 어디서 쓰는지·핵심 동작·완료 기준 중 결과에 크게 영향을 주는 누락만 골라 중요한 질문부터 하나씩 한다. 화면 느낌은 화면이 중요한 과제에서만 묻는다. `예쁘게`처럼 모호한 답에는 구체 예시나 선택지 2~3개와 다른 선택 여지를 제시한다. 모르겠다면 이유를 붙인 단순한 기본안을 추천하고 중요한 가정만 확인한다.

답을 모으면 무엇을 만들지·필수 동작·제외할 것·완료 확인 방법을 짧게 정리해 의도를 확인한다. 이미 명확한 지시는 긴 질문 절차를 생략한다. 시간 제약을 고려하고 단순한 요청에 로그인이나 복잡한 저장 구조를 임의로 붙이지 않는다. 다른 스킬을 자동으로 이어 실행하지 않는다.

핵심 기능이 완성되면 실제 코드의 입력→처리→저장→출력과 관련 파일을 짧게 설명한다. 예를 들어 메모 입력을 어디서 검사하고 어디에 저장해 어떤 화면에 보여주는지 연결한다. 저장하지 않는 기능이라면 저장이 없다고 설명한다. 중요한 오류는 원인과 수정 이유도 연결한다.

완료 검증에서는 실제 코드의 선택 이유·데이터 흐름·예외 처리·요구 변경 영향 중 중요한 주제로 한 번에 한 질문만 한다. 데이터 흐름은 입력값이 처리돼 결과가 되는 순서로, 메모 기능에서는 입력란부터 화면 표시까지 이어지는 부분이다. 사용자가 먼저 자기 말로 답한 뒤 코드와 비교해 빠진 이해를 설명한다. 매번 모든 주제를 묻거나 퀴즈를 강제하지 않으며, 답을 먼저 외우게 하지 않는다. AI의 추천·설명을 사용자가 실제 내린 판단으로 기록하지 않고 실행 검증 결과와 이해 확인 상태를 구분한다.

비전공자가 모를 용어·약어는 첫 등장에 쉬운 한국어 뜻과 현재 작업의 예시를 함께 설명한다. 다른 어려운 용어로만 풀지 않고 이미 이해한 용어는 반복을 줄인다. 뜻이 불명확한 `moc`는 `mock` 등으로 단정하지 않고 등장한 문장·파일의 맥락을 확인한다. AI의 재진술이나 요약만으로 응시자의 이해를 인증하지 않는다.

## 배포 기준

공개 저장소: https://github.com/keepbridge-ui/probe-prep-skills

커밋(commit)은 변경을 나중에 찾아보거나 되돌릴 수 있게 저장하는 기록이다. 예를 들어 세 스킬과 안내문을 함께 고친 상태를 하나의 기록으로 남길 수 있다. SHA는 그 기록을 정확히 가리키는 식별값이다.

이 보강본은 게시 후 확인해 안내하는 전체 SHA로 버전을 고정해 가져온다. 기존 초기판 `c8b36af7651939b8433135c970c2d01e0706de92`에는 대안 비교·쉬운 설명·한 질문씩 이해 확인을 보강한 내용이 없다. `main`이라는 이름의 최신 게시 상태만으로 버전을 추정하지 않는다. 출처 문서의 pstack·superpowers 저장소는 참고 원본이며 이 패키지의 배포 주소가 아니다.

## 시험 제공 Codex에서 가져오기

이 안내는 로컬 설치를 실행하지 않는다. 최신 시험 안내가 공개 자료 취득과 프로젝트 지침 등록을 허용하는지 먼저 확인한 뒤 **시험에서 제공된 Codex에게** 요청한다.

1. 확인된 공개 HTTPS 저장소 URL과 고정 커밋으로 과제 프로젝트 밖의 별도 임시 폴더에 clone·다운로드한다. 개인 로그인·토큰·API 키가 필요한 비공개 자료로 대체하지 않는다. 시험 문제·파일을 외부로 보내지 않는다.
2. 취득한 파일의 커밋, 출처·라이선스·내용과 허용 범위를 확인한다. 파일 다운로드 자체를 시험 환경에서의 사용 승인으로 간주하지 않는다.
3. 제공된 Codex 버전에서 프로젝트 스킬 경로와 명시 호출을 지원하는지 확인한다. 허용된다면 `.agents/skills/` 아래의 세 폴더에서 `SKILL.md`와 `agents/openai.yaml`만 기존 과제 프로젝트의 같은 상대 경로에 추가한다. 숨김 폴더 `.agents`를 빠뜨리지 않는다. 기존 시험 파일·디렉터리·동명 스킬을 덮어쓰거나 삭제하지 않는다. `plan`, `build`, `check`는 흔한 이름이므로 같은 이름의 대상이나 스킬이 이미 있으면 덮어쓰지 말고 해당 복사만 중단해 알린다. 기존에 설치된 다른 이름의 스킬도 자동으로 삭제하지 않는다.
4. 루트 `LICENSE`, `THIRD_PARTY_NOTICES.md`, `SOURCES.ko.md`, `SOURCES.json`, `licenses/`도 출처 고지로 함께 보존한다. 기존 과제 파일과 겹치지 않도록 `.agents/skills/probe-prep-notices/` 전용 폴더에 원래 상대 구조로 보존한다. 이 고지 폴더에는 SKILL.md를 만들지 않는다. 동명 폴더가 있으면 덮어쓰지 말고 알린다. 전체 저장소나 일반 검증 예제를 과제 제출물에 불필요하게 복사하지 않는다. 전역 설치·전역 설정 변경은 하지 않는다.
5. 제공 버전이 지원하는 `/skills` 목록이나 `$` 스킬 선택에서 세 이름을 확인한다. 실제 `SKILL.md`를 읽었는지 확인할 때는 가상 예제를 사용한다. 목록에 없으면 프로젝트 위치와 버전 지원을 먼저 확인한다. 임의의 전역 설정·심볼릭 링크·다른 도구로 제한을 우회하지 않는다.
6. 등록을 지원하지 않거나 목록에 계속 없다면 최신 안내가 로컬 지침 읽기를 허용하는 경우에만, 다운로드한 해당 `SKILL.md`의 실제 경로를 명시해 읽고 적용하도록 요청한다. 이 경우 호스트에 스킬이 등록됐다고 주장하지 않는다. 허용 여부가 불명확하면 그 사용을 보류한다.

공식 [Codex Build skills 문서](https://learn.chatgpt.com/docs/build-skills)에서 프로젝트 `.agents/skills/`, `name`·`description` frontmatter, 명시 호출과 호출 정책을 확인했다. **실제 시험 제공 버전의 경로·호출 호환성은 확인이 필요하며, 체험 환경 설정이 본시험에 유지되는지는 미확인이다.**

## AI 허용 구현 단계의 시작 프롬프트

스킬 취득·적용이 허용되고 실제로 읽힌 것을 확인한 뒤 사용한다.

```text
$plan
현재 제공된 과제 안내와 기존 코드를 먼저 읽어줘.
확정 요구·중요한 미확정 사항·완료 근거를 짧게 정리하고,
모호하면 완성된 기획서를 요구하지 말고 결과를 바꾸는 중요한 질문 하나씩으로 구체화해줘.
모르겠다고 하면 이유를 붙인 단순한 기본안을 제안해줘. 명확하면 긴 질문 절차는 생략해줘.
아직 정하지 않은 중요한 구조 선택은 쉬운 대안·장단점·추천 이유를 설명해 내가 판단하게 해줘.
모를 만한 기술 용어는 쉬운 뜻과 현재 작업의 예시로 풀어주고, 사소한 수정마다 승인을 묻지는 마.
최신 시험 규칙을 우선하고 시험 자료를 외부로 보내지 마.
```

구현·수정 시에는 `$build`, 완료·제출 직전에는 `$check`를 각각 명시한다. 매번 현재 코드와 마지막 변경 이후의 증거를 사용한다. 스킬이 실제로 선택되거나 읽히지 않았다면 사용했다고 간주하지 않는다. 제출 자체는 자동화하지 않는다.

핵심 기능이 완성된 뒤의 짧은 요청 예시:

```text
$check
실제 코드와 실행 결과로 완료 여부를 확인해줘.
중요한 선택이나 기능 한 곳을 골라 한 질문만 하고 내가 먼저 답하게 해줘.
내 답변 뒤에 코드와 비교해 빠진 이해를 쉽게 설명해줘.
```

## 검증과 출처

[검증 요약](VERIFICATION.ko.md)은 구조 검사·실제 가상 코드 실행·관찰된 행동과 한계를 구분한다. [일반 가상 시나리오](verification/SCENARIOS.ko.md)는 재사용 가능한 입력과 확인 기준을 제공한다. 개인 환경 경로·내부 대화·상세 실행 로그는 공개본에 포함하지 않는다.

[설계 출처](SOURCES.ko.md)와 [고정 출처 기록](SOURCES.json)에 원본별 커밋·원칙·해시가 있다. [제3자 고지](THIRD_PARTY_NOTICES.md)와 `licenses/`에 두 MIT 고지 전문을 보존했다.
